# Limits of v0.1.0

- The supported engine is restic 0.20.0 with a local filesystem repository. Use canonical paths on a local disk. Network shares, mapped remote drives, remote backend syntax and cross-OS snapshot path translation are outside the supported setup. POSIX cannot reliably identify every remote mount, same-device bind mount or alias. The operator must establish the actual filesystem topology.
- The operator controls the repository and its directory hierarchy, the binary, PATH, workspace, system temp directory and their ancestors throughout the run. A hostile local account with write access, a compromised binary, changing mount table, malicious repository administrator or compromised host can defeat these assumptions. The auditor does not authenticate a binary by its reported version. Verify its download.
- Executed recovery requires non-elevated privileges. POSIX workspace ownership and write bits are checked. On Windows the user must verify inherited ACLs. Only regular files and ordinary directories with supported names and modes are accepted. Links, special nodes, suspicious hard links, name collisions, non-NFC archive names and some otherwise legal filenames are rejected. Repeated inode numbers can conservatively rule out a safe tree. Windows reparse checks cannot make a changing directory race-free.
- Default limits are 10,000 files, 1 GiB of logical file data and 120 seconds per restic command. Configurable maxima are 50,000 files, 16 GiB and 24 hours. Inventory also caps all nodes at 50,000, depth at 64, paths at 4,096 UTF-8 bytes, components at 255 bytes, listing output at 32 MiB and each line at 128 KiB. Snapshot metadata is limited to 10,000 snapshots and 8 MiB. Stderr is capped at 1 MiB per command. Limit failures can leave a partial restore.
- A full repository check may read far more than the restore budget. Budget and free-space calculations use logical sizes and cannot reserve blocks, account for every allocation or enforce a quota on restic. Use adequate local storage and account for competing I/O. A timeout can interrupt useful work.
- Snapshot timestamps and source labels depend on the backup host. Changes after snapshot creation, omitted inputs, application-level consistency and intentional tampering by an authorized writer require independent evidence. The CLI does not consume a signed source manifest or validate scientific correctness.
- Plaintext persists under the generated sandbox after an attempted restore. Neither automatic removal nor secure erasure is provided. The demo's random password lasts only for its process. Its repository is disposable.
- Regular offline or immutable copies, separate credentials, independent baselines and a tested recovery procedure address failure modes that one local repository cannot. This release has no real-dataset measurements or independent security certification.
